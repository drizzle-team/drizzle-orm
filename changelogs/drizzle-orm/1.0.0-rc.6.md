# v1.0.0-rc.6

- Breaking changes:
  - Drivers no longer configure output decoding in drivers' configurations - following configurations set by drizzle constructors were removed:
    - `client.options.bigint = true` from `bun-sql/postgres`, `bun-sql/mysql`
    - transparent decoders from `postgres-js`
    - global `types.setTypeParser(...)` from `neon-http`, `netlify-db`
    - per-query parser overrides from `node-postgres`, `node-postgres/dsql`, `vercel-postgres`, `neon-serverless`, `netlify-db`, `cockroach`, `pglite`
    - per-query `typeCast` from `mysql2`  

    :exclamation:`postgres-js` still overrides client's param serializers (client-wide, replacing user-configured ones) for `timestamptz` (`1184`), `timestamp` (`1114`), `date` (`1082`), `time` (`1083`) and their arrays:
    - `Date` values are sent as `value.toISOString()` - same as `postgres.js`' default for `timestamptz`, `timestamp`, `date`
    - strings are sent as is to be parsed by the server - `postgres.js`' default re-encodes them via `new Date(value).toISOString()`, which reads offset-less timestamps in process' local time, truncates microseconds and throws on values JS can't parse (`'infinity'`, `'12:00:00'`)
    - `time` switches `Date` processing from `date.toString()` to ISO string

    Driver config overrides were replaced with cast to text codecs for types:
  - `pg`, `cockroach`: `bigint`, `bigserial`, `numeric`, `date`, `time`, `timestamp`, `interval`, `json`, `jsonb` and their array versions
  - `mysql`, `singlestore`: `decimal`, `date`, `datetime`, `timestamp`, `time`, `json`

    `sqlite`: integer-based codecs (`integer`, `integer:boolean`, `integer:timestamp`, `integer:timestamp_ms`) accept `number`, `bigint` and integer text, which makes them independent of safe integer modes (`better-sqlite3`'s `defaultSafeIntegers`, `bun:sqlite`'s `safeIntegers`, `node:sqlite`'s `readBigInts`, `libsql`'s `intMode`)

    :exclamation: Results of raw queries (`db.execute(sql...)`, `sql` fields without a column's decoder) now honor driver's configuration

    `pg-proxy`, `mysql-proxy`, `singlestore-proxy` servers no longer need to replicate drizzle's driver result type configurations (e.g. returning `timestamp`, `date`, `interval` as strings via `types.setTypeParser(...)` / `typeCast`)

    :warning: Codecs only cover client options with predictable output (`bigint`, `safeIntegers`, `intMode`, `decimalNumbers`, `jsonStrings`, ...). Custom parsing functions (`pg`'s `types.setTypeParser(...)` / `types.getTypeParser`, `postgres`' `types`, `mysql2`'s `typeCast`) that change output of types drizzle doesn't cast still require custom codecs, e.g.:

    ```ts
    import { refineCodecs } from 'drizzle-orm/codecs';
    import { drizzle, mysql2Codecs } from 'drizzle-orm/mysql2';
    import { createPool } from 'mysql2/promise';

    const client = createPool({
      uri: process.env.DATABASE_URL,
      typeCast: (field, next) => {
        // `tinyint(1)` is returned as `boolean` instead of `number`
        if (field.type === 'TINY' && field.length === 1) return field.string() === '1';
        // `BLOB`-typed fields (`text`, `blob` columns) are returned as `Buffer` instead of `string`
        if (field.type === 'BLOB') return field.buffer();
        return next();
      },
    });

    const fromBuffer = (value: Buffer) => value.toString('utf8');

    const db = drizzle({
      client,
      codecs: refineCodecs(mysql2Codecs, {
        // default `boolean` codec expects `0` / `1` - client's output is already final
        boolean: { normalize: undefined },
        // text codecs have no decoders by default - client's output is expected to be a string
        text: { normalize: fromBuffer },
        mediumtext: { normalize: fromBuffer },
      }),
    });
    ```

    ```ts
    import { refineCodecs } from 'drizzle-orm/codecs';
    import { arrayCompatNormalize } from 'drizzle-orm/pg-core';
    import { drizzle, postgresJsCodecs } from 'drizzle-orm/postgres-js';
    import postgres from 'postgres';

    type Line = [a: number, b: number, c: number];

    const client = postgres(process.env.DATABASE_URL, {
      types: {
        // `point` (and `point[]`) is returned as `{ x, y }` instead of `(x,y)` text
        point: {
          to: 600,
          from: [600],
          // drizzle already encodes points to `(x,y)` text
          serialize: (value: string) => value,
          parse: (value: string) => {
            const [x, y] = value.slice(1, -1).split(',').map(Number);
            return { x, y };
          },
        },
        // `line` (and `line[]`) is returned as `[a, b, c]` instead of `{a,b,c}` text, params are expected as `[a, b, c]`
        line: {
          to: 628,
          from: [628],
          serialize: ([a, b, c]: Line) => `{${a},${b},${c}}`,
          parse: (value: string) => value.slice(1, -1).split(',').map(Number) as Line,
        },
      },
    });

    const toABC = ([a, b, c]: Line) => ({ a, b, c });

    const db = drizzle({
      client,
      codecs: refineCodecs(postgresJsCodecs(client), {
        // default `point` codecs parse `(x,y)` text - client's output is already final
        point: { normalize: undefined, normalizeArray: undefined },
        // `line({ mode: 'abc' })` columns
        line: {
          normalize: toABC,
          normalizeArray: arrayCompatNormalize(toABC),
          // drizzle encodes `{ a, b, c }` to `{a,b,c}` text - array params stay array literals, which `postgres.js` sends as is
          normalizeParam: (value: string) => value.slice(1, -1).split(',').map(Number) as Line,
        },
      }),
    });
    ```

  - Changed `postgresJsCodecs` (`drizzle-orm/postgres-js`, `drizzle-orm/postgres-js/dsql`), `bunSqlPgCodecs` (`drizzle-orm/bun-sql/postgres`) from plain objects to `(client) => codecs` functions due to `json` param wrapper functions only being accessible from drivers via `client.json(param)`
  - Fixed `bun-sql/mysql` `datetime` in `string` returning trailing zeroes for empty second fractions
- Fixed `effect-postgres` failing to encode empty array params (`Cannot infer the type of an empty array`) of `text`, `varchar`, `char`, `bool`, `smallint`, `int`, `bigint`, serial types, `float4`, `float8`, `bytea` columns (fixes [#6566](https://github.com/drizzle-team/drizzle-orm/issues/6566))
- Fixed `effect-postgres` `bigint`, `bigserial` columns in `bigint` mode returning strings when `PgClient` decodes `int8` as text (fixes [#6566](https://github.com/drizzle-team/drizzle-orm/issues/6566))
- Fixed `bun-sql` `postgres` `bigint`, `bigserial` columns in `bigint` mode returning strings since `bun` started ignoring `options.bigint` set after client's construction
- Fixed `bun-sql` `postgres` empty multidimensional `integer` arrays being returned as `Int32Array`
- Fixed `is()` narrowing columns to `never`:
  - `pg`: `text`, `varchar`, `char` with `enum` (`is(column, PgText)`), plain `varchar`, `char`
  - `cockroach`: `cockroachEnum` columns (`is(column, CockroachEnumColumn)`)
  - `mysql`: `blob`, `tinyblob`, `mediumblob`, `longblob` in `buffer` mode (`is(column, MySqlBufferBlob)`)
- Fixed `mysql`, `singlestore` enum columns narrowed by `is()` having `column.enumValues` typed as `| undefined`
- Fixed `cockroach` `cockroachEnum` columns being typed with `string` `dataType` instead of `string enum`, which made validators infer `string` instead of the enum's values
- Fixed `mysql` `blob`, `tinyblob`, `mediumblob`, `longblob` in `buffer` mode having `string` `dataType` instead of `object buffer`, which made validators generate string schemas for `Buffer` values
- Fixed validators inferring `string` instead of enum members for columns of enums made from TS enums (`pgEnum`, `cockroachEnum`, `mysqlEnum`)
- Fixed `drizzle-orm/zod` `createSchemaFactory` without `coerce` option breaking refine callbacks' parameter type inference (`Parameter 'schema' implicitly has an 'any' type`) (fixes [#5968](https://github.com/drizzle-team/drizzle-orm/issues/5968))
- Fixed `postgres-js` errors on `json`, `jsonb` columns' params with `boolean`, `Date`, `Buffer`, `Uint8Array` values and arrays starting with them  (`column "..." is of type jsonb but expression is of type ...`) (fixes [#6582](https://github.com/drizzle-team/drizzle-orm/issues/6582))
- Fixed `bun-sql/postgres` errors on `json`, `jsonb` columns' params with top-level `number`, `boolean`, `Buffer`, `Uint8Array` values (fixes [#6591](https://github.com/drizzle-team/drizzle-orm/issues/6591))
- Fixed `bun-sql/postgres` with `prepare: false` errors on `json`, `jsonb` columns' params (fixes [#6132](https://github.com/drizzle-team/drizzle-orm/issues/6132))
- Fixed `node-postgres`, `neon-serverless`, `vercel-postgres`, `netlify-db` errors on `json`, `jsonb` columns' params with `Date`, `Buffer`, `Uint8Array` values (`invalid input syntax for type json`)
- Fixed type errors in emitted declarations with `skipLibCheck: false` (fixes [#5187](https://github.com/drizzle-team/drizzle-orm/issues/5187)):
  - `Cannot find module 'mysql2'` in projects without `mysql2` installed - general modules (`drizzle-orm`, `drizzle-orm/pg-core`, ...) no longer reference driver packages' types
  - `Class 'PgRole' incorrectly implements interface 'PgRoleConfig'` (same for `PgPolicy`, `CockroachRole`, `CockroachPolicy`) with `exactOptionalPropertyTypes` 
  - `Type 'Buffer' is not generic` on TypeScript 5.6 and older in `mysql-core` `blob` codecs and `drizzle-orm/arktype`'s `bufferSchema`
- Fixed `mssql`, `@types/mssql` peer dependencies having versions fixed to `^` instead of `>=`

# v1.0.0-rc.6

- Breaking changes:
  - Drivers no longer configure output decoding in drivers' configurations - following configurations set by drizzle constructors were removed:
    - `client.options.bigint = true` from `bun-sql/postgres`, `bun-sql/mysql`
    - transparent decoders from `postgres-js`
    - global `types.setTypeParser(...)` from `neon-http`, `netlify-db`
    - per-query parser overrides from `raw` mode and other queries not decoded by codecs (`node-postgres`, `node-postgres/dsql`, `vercel-postgres`, `neon-serverless`, `netlify-db`, `cockroach`, `pglite`, `mysql2`)

    :exclamation:`postgres-js` still overrides client's param serializers (client-wide, replacing user-configured ones) for `timestamptz` (`1184`), `timestamp` (`1114`), `date` (`1082`), `time` (`1083`) and their arrays:
    - `Date` values are sent as `value.toISOString()` - same as `postgres.js`' default for `timestamptz`, `timestamp`, `date`
    - strings are sent as is to be parsed by the server - `postgres.js`' default re-encodes them via `new Date(value).toISOString()`, which reads offset-less timestamps in process' local time, truncates microseconds and throws on values JS can't parse (`'infinity'`, `'12:00:00'`)
    - `time` switches `Date` processing from `date.toString()` to ISO string

    `sqlite`: integer-based codecs (`integer`, `integer:boolean`, `integer:timestamp`, `integer:timestamp_ms`) accept `number`, `bigint` and integer text, which makes them independent of safe integer modes (`better-sqlite3`'s `defaultSafeIntegers`, `bun:sqlite`'s `safeIntegers`, `node:sqlite`'s `readBigInts`, `libsql`'s `intMode`)

    :exclamation: Results of raw queries (`db.execute(sql...)`) now honor driver's configuration

    :warning: Codecs only cover client options with predictable output (`bigint`, `safeIntegers`, `intMode`, `decimalNumbers`, `jsonStrings`, ...). Custom parsing functions (`pg`'s `types.setTypeParser(...)` / `types.getTypeParser`, `postgres`' `types`, `mysql2`'s `typeCast`) that change output of types drizzle doesn't request per query still require custom codecs, e.g.:

    ```ts
    import { refineCodecs } from 'drizzle-orm/codecs';
    import { drizzle, mysql2Codecs } from 'drizzle-orm/mysql2';
    import { createPool } from 'mysql2/promise';

    const client = createPool({
      uri: process.env.DATABASE_URL,
      typeCast: (field, next) => {
        // `tinyint(1)` is returned as `boolean` instead of `number`
        if (field.type === 'TINY' && field.length === 1) return field.string() === '1';
        // `BLOB`-typed fields (`text`, `blob` columns) are returned as `Buffer` instead of `string`
        if (field.type === 'BLOB') return field.buffer();
        return next();
      },
    });

    const fromBuffer = (value: Buffer) => value.toString('utf8');

    const db = drizzle({
      client,
      codecs: refineCodecs(mysql2Codecs, {
        // default `boolean` codec expects `0` / `1` - client's output is already final
        boolean: { normalize: undefined },
        // text codecs have no decoders by default - client's output is expected to be a string
        text: { normalize: fromBuffer },
        mediumtext: { normalize: fromBuffer },
      }),
    });
    ```

    ```ts
    import { refineCodecs } from 'drizzle-orm/codecs';
    import { arrayCompatNormalize, arrayCompatNormalizeInput } from 'drizzle-orm/pg-core';
    import { drizzle, postgresJsCodecs } from 'drizzle-orm/postgres-js';
    import postgres from 'postgres';

    type Line = [a: number, b: number, c: number];

    const client = postgres(process.env.DATABASE_URL, {
      types: {
        // `point` (and `point[]`) is returned as `{ x, y }` instead of `(x,y)` text
        point: {
          to: 600,
          from: [600],
          // drizzle already encodes points to `(x,y)` text
          serialize: (value: string) => value,
          parse: (value: string) => {
            const [x, y] = value.slice(1, -1).split(',').map(Number);
            return { x, y };
          },
        },
        // `line` (and `line[]`) is returned as `[a, b, c]` instead of `{a,b,c}` text, params are expected as `[a, b, c]`
        line: {
          to: 628,
          from: [628],
          serialize: ([a, b, c]: Line) => `{${a},${b},${c}}`,
          parse: (value: string) => value.slice(1, -1).split(',').map(Number) as Line,
        },
      },
    });

    const toABC = ([a, b, c]: Line) => ({ a, b, c });
    const toLine = (value: string) => value.slice(1, -1).split(',').map(Number) as Line;

    const db = drizzle({
      client,
      codecs: refineCodecs(postgresJsCodecs(client), {
        // default `point` codecs parse `(x,y)` text - client's output is already final
        point: { normalize: undefined, normalizeArray: undefined },
        // `line({ mode: 'abc' })` columns
        line: {
          normalize: toABC,
          normalizeArray: arrayCompatNormalize(toABC),
          // drizzle encodes `{ a, b, c }` to `{a,b,c}` text
          normalizeParam: toLine,
          // `postgres.js` 4 serializes array params element by element, with the type's `serialize` - elements are typed,
          // or it would read the tuples as nested arrays
          normalizeParamArray: arrayCompatNormalizeInput((value: string) => client.typed(toLine(value) as any, 628)),
        },
      }),
    });
    ```

  - Removed cast codecs: selected columns are no longer wrapped in casts (`::text`, `cast(... as char)`, epoch milliseconds, ...) and set operations in `select ... from (...) "drizzle_union"` (except `singlestore`); `toSQL()` / `getSQL()` of query builders lost their `withCastCodecs` switch. This fixes `select distinct ... order by <column>` being invalid on `pg`, `cockroach`, `mysql`, `mssql` (fixes [#6673](https://github.com/drizzle-team/drizzle-orm/issues/6673)). Changes that came with it:
    - Returned data:
      - Queries decoded by codecs (with a mapper - not `db.execute`, `db.call`) request lossless output per query; the overrides are exported for proxy servers, which apply them in their own callback implementations (`nodePgRawTextTypes`, `nodePgDsqlRawTextTypes`, `neonServerlessRawTextTypes`, `neonHttpRawTextTypes`, `vercelPgRawTextTypes`, `netlifyDbRawTextTypes`, `nodeCockroachRawTextTypes`, `pgliteRawTextParsers`, `decodePostgresJsRawRows`, `makeMySql2RawTextTypeCast`, `makeSingleStoreRawTextTypeCast`, `makePlanetscaleRawTextCast`, `tidbRawTextDecoders`, `awsDataApiRawTextResultSetOptions`):
        - `node-postgres`, `node-postgres/dsql`, `neon-serverless`, `neon-http`, `vercel-postgres`, `netlify-db`, `cockroach`: per-query `types` returning `date`, `timestamp`, `timestamptz`, `interval`, `numeric[]` and their arrays as text (fixes [#6290](https://github.com/drizzle-team/drizzle-orm/issues/6290)); `pglite`: per-query `parsers` for the same types; `postgres-js`: `raw` mode, decoding the same types as text and others with the client's own parsers
        - `mysql2`, `singlestore`: per-query `typeCast` (`bigint`, `decimal`, `date`, `datetime`, `timestamp` as text, `json` parsed, other fields through the client's own `typeCast`); `planetscale-serverless`: per-query `cast`; `tidb-serverless`: per-query `decoders`; `aws-data-api/pg`: `longReturnType: 'STRING'`
        - `better-sqlite3`, `node-sqlite`, `bun-sqlite`, `tursodatabase`, `tursodatabase-sync`, `tursodatabase-serverless`, `effect-sqlite-node`, `effect-sqlite-bun`: integers as `bigint`s per statement, so `numeric` keeps integers past the safe range. :exclamation: Integer `sql` fields without `.mapWith()` are `bigint`s on these drivers
      - Other drivers' output is decoded as returned. Column types the driver returns with data already lost throw `Column type "<type>" is not supported with the <driver> driver: <reason>` (each driver's `drizzle()` docs list them, with quirks):
        - `pg`, `cockroach` drivers decoding text: temporal values in sessions with non-ISO `DateStyle`
        - `bun-sql/postgres`, `effect-postgres`, `effect-pglite`, `aws-data-api/pg`, `postgres/aurora`: `timestamptz` in `string` mode (offset of the session's time zone dropped)
        - `effect-pglite`: `timestamp` (process-local time)
        - `effect-postgres`: `macaddr`, `macaddr8`, `enum[]`, `geometry`, `vector`, `halfvec`, `sparsevec` (binary format decoded as corrupted text); `point`, `line`, `bit`, `interval[]`, multidimensional arrays fail in the driver
        - `aws-data-api/pg`, `postgres/aurora`: `timetz` (offset dropped), `bytea[]` (returned empty)
        - `node-mssql`: `decimal`, `numeric` in `string` mode, values past the safe range in `bigint` mode
        - `d1`, `sql-js`, `expo-sqlite`, `op-sqlite`, `durable-sqlite`, `sqlite-cloud`, `effect-d1`, `effect-sqlite-do`: `numeric` integers past the safe range (`libsql`, `effect-libsql` with `intMode: 'number'` fail in the driver)
      - Driver quirks, decoded as returned: `float` rounded to 6 significant digits (`mysql2`, `singlestore`, `planetscale-serverless`; `bun-sql/mysql` in queries without bound parameters); `time` cut to milliseconds, `BC` dropped from fractional `timestamp`s, `null` array elements dropped (`aws-data-api/pg`, `postgres/aurora`); BC `date`s read as `Invalid Date`s, years 1 - 99 of `timestamptz` read as 19xx (`effect-pglite`); microseconds of string-mode `timestamp`, `datetime` (`bun-sql/postgres`, `bun-sql/mysql`, `effect-postgres`)
      - Set operation fields are decoded by the left-hand side's codec (`pg`, `cockroach`, `mssql`, `singlestore`) or the codec of the combined type (`mysql`, `sqlite`); `sqlite` `blob` ∪ `numeric` `bigint` fields are decoded per row by the storage class they came in
      - `bun-sql/postgres`: `infinity`, `-infinity` dates and timestamps (`Infinity` numbers from `bun`) are decoded to `Invalid Date`s, `'infinity'` / `'-infinity'` in `string` mode
    - Drizzle instance creation:
      - `effect-mysql2`: `make` rejects clients created without `dateStrings: true` (`poolConfig`, or `?dateStrings=true` in `url`) or with `decimalNumbers: true`
      - `bun-sql/sqlite`: `drizzle()` rejects `SQL` clients created without `safeIntegers: true` (or `bigint: true`), clients it creates from connection strings set it
    - Corrections of earlier release notes:
      - rc.4 "Fixed `mysql` `float` rounding": holds for `effect-mysql2` only, other drivers round per the quirk above
      - rc.4 "Fixed `mysql` cropping `.000` from `timestamp(3)`": holds except for `effect-mysql2`, `bun-sql/mysql`, which drop trailing zeros of fractional seconds
      - rc.4 set operator `drizzle_union` wrapping and combined-type codecs: see set operations above
      - rc.5 `bun-sql/mysql`, `mysql2`, `singlestore` "`cast` codecs": replaced by per-query `typeCast` (`mysql2`, `singlestore`) and decoding as returned (`bun-sql/mysql`)
      - rc.5 `withCastCodecs` switch, "Fixed cast codecs being applied to selection fields of inner queries", "Fixed `sqlite` generating `View`, `Subquery` queries with `cast` on `numeric` columns": no longer apply
      - rc.5 "Fixed `mysql` `date` column being affected by server's timezone" ([#1442](https://github.com/drizzle-team/drizzle-orm/issues/1442)): `effect-mysql2` requires `dateStrings: true` for it
      - rc.5 "Fixed `effect-mysql`, `bun-sql/mysql` drivers losing `time` fraction": `effect-mysql2` drops trailing zeros of the fraction
      - rc.5 `aws-data-api/pg` `time({ withTimezone: true })` results converted to UTC: such columns throw now (see above)
  - `postgres-js`: supported `postgres` 4 (`json[]`, `jsonb[]` params are sent as typed elements on 4, as array literals on 3); bumped the tested version to `4.1.1` - `postgres` before 4.0.0 decodes `null` array elements as `NaN`, `'NULL'`, `false` or throws (`json`, `jsonb`)
  - Changed `postgresJsCodecs` (`drizzle-orm/postgres-js`, `drizzle-orm/postgres-js/dsql`), `bunSqlPgCodecs` (`drizzle-orm/bun-sql/postgres`) from plain objects to `(client) => codecs` functions due to `json` param wrapper functions only being accessible from drivers via `client.json(param)`
  - Fixed `bun-sql/mysql` `datetime` in `string` returning trailing zeroes for empty second fractions
  - Bumped minimal supported version of `@types/mssql` peer dependency from `9.1.4` to `9.1.11` to match declarations of `mssql@11.0.1`; changed `mssql`, `@types/mssql` peer dependency version requirements from `^` to`>=` 
  - Changed shapes of dialect-specific `concat`, `substring` expressions (`drizzle-orm/<dialect>-core/expressions`) to match their dialects' functions:
    - `mysql`, `singlestore`, `mssql`: `concat(a, b, ...rest)` now accepts any number of values (`string`, `number`, `bigint`, `Placeholder`, `SQLWrapper`) and emits `concat(...)` instead of `||`, which is a logical `OR` in `mysql`, `singlestore` and is unsupported by `mssql` before SQL Server 2025
    - `mysql`, `singlestore`: `substring(column, { from, for? })` - `from` is now required (`substring(x for n)` is a syntax error); `from`, `for` accept `bigint`
    - `pg`, `cockroach`: `substring(column, { from?, for? })` now requires at least one of `from`, `for` (`substring(x)` is an error); `from` is cast to `integer` (`pg`) / `int8` (`cockroach`) due to `substring(text from pattern)` overload being picked by default; `cockroach` positions accept `bigint`
    - `pg`, `cockroach`: added regular expression `substring` overloads:
      - `substring(column, { fromPattern })` - POSIX regular expression (`substring(x from pattern)`)
      - `pg`: `substring(column, { similar, escape })` - SQL regular expression (`substring(x similar pattern escape escape)`)
      - `cockroach`: `substring(column, { fromPattern, escape })` - POSIX regular expression with `escape` in place of `\` (`substring(input, regex, escape_char)`)
    - `sqlite`: `substring(column, { from?, for? })` -> `substring(column, start, length?)`, emits `substr(x, start[, length])` instead of unsupported `substring(x from ... for ...)`; `start`, `length` accept `bigint`
    - `mssql`: `substring(column, { from?, for? })` -> `substring(column, start, length)`, emits `substring(x, start, length)` instead of unsupported `substring(x from ... for ...)`
    - `concat` values and `substring` arguments are no longer encoded with the column's encoder - they are not expected to share the column's type
  - Fixed subqueries selected as fields being inferred as non-nullable - a subquery can return no rows, so their values are now typed as `| null`. This also applies to such fields re-selected from views and subqueries built from these selections:

    ```ts
    const res = await db.select({
      id: users.id,
      // before: number, now: number | null
      lastPostId: db.select({ id: posts.id }).from(posts).where(eq(posts.authorId, users.id)).orderBy(desc(posts.id)).limit(1).as('last_post_id'),
    }).from(users);
    ```
  - `upstash` cache now stores query results in a binary format instead of JSON, which turned values JSON can't represent into different types on cache hits. Results are encoded to a base64 string with a `dzb1:` prefix - entries written by previous versions are treated as cache misses. Serialization can be replaced with the `serializer` option:

    ```ts
    import { upstashCache } from 'drizzle-orm/cache/upstash';

    const cache = upstashCache({
      url: process.env.UPSTASH_REDIS_REST_URL!,
      token: process.env.UPSTASH_REDIS_REST_TOKEN!,
      // default: `binarySerializer` from `drizzle-orm/cache/core`
      serializer: {
        serialize: (response) => JSON.stringify(response),
        // values are received as returned by `@upstash/redis`; `undefined` is a cache miss
        deserialize: (value) => typeof value === 'string' ? JSON.parse(value) : value,
      },
    });
    ```

    The binary format serializer is importable from `drizzle-orm/cache/core` for custom caches: `serializeBinary` / `deserializeBinary` (`Uint8Array`), `binarySerializer` (`{ serialize, deserialize }` of prefixed base64 text; deserializer returns `undefined` on foreign payloads)
  - `sqlite`: `.run()` is no longer read from or written to cache - it returns driver's run result instead of rows. Mutations executed by `.run()` still invalidate cache

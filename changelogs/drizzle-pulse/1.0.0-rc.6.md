# v1.0.0-rc.6

`drizzle-pulse` is a type-safe realtime SDK for Drizzle ORM: it streams row changes from PostgreSQL's write-ahead log
(`wal_level = logical`) to consumers subscribed to queries you define on the server. Its version now follows the other
Drizzle packages.

```ts
import { drizzle } from 'drizzle-orm/postgres';
import { pulse } from 'drizzle-pulse';
import { createRuntime } from 'drizzle-pulse/embedded';
import { z } from 'zod';
import { orders } from './schema.ts';

// Queries are defined once, on the server; `.args()` takes any Standard Schema
const ordersByStatus = pulse(orders)
  .args(z.object({ status: z.enum(['requested', 'accepted', 'completed', 'cancelled']) }))
  .query((ctx) => ctx.query({ status: ctx.args.status }));

const runtime = createRuntime({
  queries: { ordersByStatus },
  databaseUrl: process.env.DATABASE_URL!,
  // the app's own connection: baseline reads keep it's session context (RLS, `search_path`)
  sourceDb: drizzle(process.env.DATABASE_URL!),
});

// provisions the publication, replication slot and events tables, then starts reading the WAL
await runtime.start();

// Live collection: current result, kept up to date
const accepted = await runtime.client.ordersByStatus({ status: 'accepted' });
console.log(accepted.list());
accepted.onChange(({ events, state }) => console.log(events, state));

// CDC event stream: `insert` / `update` / `delete` relative to the query's result
const unsubscribe = runtime.events.ordersByStatus({ status: 'accepted' }, (event, lsn) => console.log(event.op, lsn));
```

Breaking changes:
- Peer dependencies: `drizzle-orm` raised to `^1.0.0-rc.6`; removed `@drizzle-team/minipg` - Pulse uses the Drizzle Postgres driver that `drizzle-orm` bundles (`drizzle-orm/postgres`, `drizzle-orm/postgres/cdc`); removed `zod` - query arguments take any Standard Schema
- CDC event stream and live collection events are relative to the query result: `insert` has `row`, `update` has the full `row` and `oldRow`, `delete` has `oldRow`. `matchesNew` and `old_row` were removed from the embedded event types, `PulseDeleteEvent` takes the row type parameter
- `.args()` takes any Standard Schema instead of only a `zod` schema; it's validation must be synchronous. Invalid args throw an error listing the issue messages
- `PulseBuilder` type parameters are now `TTable`, `TSelection`, `TArgsInput`, `TArgsOutput`, `TResult`, `TFlags`: callers pass the input type of the args schema, `ctx.args` is it's output type. `PulseBuilder.config` and it's constructor are internal
- `pulse(t).query(fn)` types `ctx.args` as `Record<never, never>`; `.args()` throws after a where-function
- Queries built with `.transform()` or `.limit()` are missing from `runtime.client` and `runtime.events` at compile time
- Opening a CDC event stream with a `where` on a column excluded by `.columns()` throws, as opening a live collection does
- Opening a live collection or a CDC event stream takes no `auth` option; removed `PulseCollectionOptions`
- `TelemetryEvent`: `committedAt`, `appliedAt` renamed to `committedAtMicros`, `appliedAtMicros` (epoch microseconds)
- `QueryDescriptor` moved from `drizzle-pulse` to `drizzle-pulse/client`; `PulseAuthContext` is exported from `drizzle-pulse` only
- `PulseCollection` has a private constructor
- `EmbeddedRuntimeConfig` is a type alias, as it takes either `databaseUrl` or `client`
- `start()` only adds tables to the publication: dropping unregistered tables from it and resetting their replica identity is done by provisioning only
- Removed the `drizzle-pulse/package.json` export

New features:
- `drizzle-pulse/embedded`: added standalone `provision({ queries, databaseUrl, wal })` - does the same as `runtime.provision()` without a runtime or `sourceDb`, for deploy steps
- `createRuntime()` and `provision()` take an optional `client` - a Drizzle Postgres `Pool` (`drizzle-orm/postgres`) - in place of `databaseUrl`. Pulse runs it's admin queries on the pool and replication through `client.replicate()`, and doesn't close the pool. Without `client`, the driver bundled with `drizzle-orm` is only imported when the runtime starts or provisions
- Added `onResync`, `onError` options for CDC event streams
- `drizzle-pulse` exports `PulseAuthContext`, `PulseQueryContext`, `WhereClause` types

Other changes:
- `ColumnOperators.in` accepts readonly arrays
- Errors and JSDoc use the terms live collection and CDC event stream, and document microsecond units, the slot name prefix and the publication rules
